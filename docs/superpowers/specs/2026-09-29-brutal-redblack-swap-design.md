# Brutal mode = the `redblack` UI (design spec)

Date: 2026-09-29 · Branch: `redesign-three-pane` · Status: draft for review

## Goal

On `redesign-three-pane`, clicking the BRUTAL button (rail 3, `components/RailThree.tsx`) must render the exact UI of the `redblack` branch (neubrutalist restyle of the old three-zone layout). Turning it off returns to today's three-pane UI, which must stay pixel-identical to how it is now.

## Decisions (agreed)

- Approach: swap in `redblack`'s layout and components (exact match), not a CSS re-skin of the three-pane.
- Palette: Brutal follows the existing light/dark toggle (`data-mode`), using `redblack`'s white+black (light) and red+black (dark) themes. The four character themes (zoro/luffy/news/shanks) do not apply in Brutal.
- Scope, pass 1: home page (`/`) and the shell (nav, identity panel, project side panel, marquee, cursor, footer, command palette). Other routes (`/blog`, `/weekly`, `/gallery`, `/work/*`, `/resume`, `/places`, `/specs`) are pass 2 and out of scope here.

## Background

`redblack` and `redesign-three-pane` both forked from `main` at `1404989`.
- `redblack` restyled the existing components (`HomeShell`, `Nav`, `ProjectCard`, `Projects`, `TaglineCycler`, ...) in `app/globals.css` (~3.0k lines).
- `redesign-three-pane` rebuilt them (`RailThree`, `StackBoard`, `WorkGrid`, `CommitSnake`, new `About`/`Nav`/`Marquee`/`CustomCursor`, ...) with its own `app/globals.css` (~3.4k lines).
- Both define the same global class names, so loading both stylesheets unscoped would clash. Today's `data-ui="brutal"` only overrides tokens; it cannot reproduce `redblack`.

## Amendment (2026-09-29, approved by user) — supersedes "Design" below

While planning, the `rb-` class-prefixing design proved unsafe: `redblack`'s TSX uses its class names in JS (`CustomCursor` selectors, `HomeShell`'s `header.site-nav` / `.loop-set`, `panelScroll`, `html.custom-cursor-active`) and relies on library-owned classes (`html.lenis`), so a rename script would silently break behaviour, and three-pane global rules would still leak into the `redblack` tree. Replaced with **route-group isolation + proxy** (Next 16.3.4 supports multiple root layouts and `proxy.ts`; verified in `node_modules/next/dist/docs`):

- `app/(three)/` = the existing app, moved (not edited) behind a route group; its root layout keeps `globals.css`.
- `app/(rb)/` = a second root layout that imports `redblack`'s `globals.css` verbatim, and `app/(rb)/rb/page.tsx` = `redblack`'s home, served at `/rb`. Components go to `components/rb/`, the three libs that differ (`data`, `panelScroll`, `useTheme`) to `lib/rb/`, all copied from `git show redblack:...` by a re-runnable script `scripts/port-redblack.mjs`. Separate root layouts load separate CSS, so nothing collides.
- `proxy.ts` rewrites `/` to `/rb` when cookie `kps-ui=brutal` is present. BRUTAL sets the cookie and reloads; a fixed `ExitBrutal` button in the `(rb)` layout clears it. Light/dark: the `(rb)` theme init/`useTheme` read and write `kps-mode` (three-pane's key) and stamp `data-theme`, so both UIs share one light/dark choice.
- Unmatched URLs use `global-not-found` (experimental flag) rendering the same three-pane document as today.
- Trade-offs: toggling is a page reload (fits the "hard cut" intent); first paint is correct (server-side rewrite, no flash); `redblack` code ships only on `/rb`; non-home routes stay three-pane in pass 1.

## Design (SUPERSEDED — kept for history)

### 1. Isolated port of `redblack`
- New dirs: `components/redblack/` and `lib/redblack/` (only files that differ from, or don't exist in, the three-pane branch; shared, unchanged modules such as `lib/site.ts` are reused).
- New stylesheet `app/redblack.css`, generated by a re-runnable script `scripts/port-redblack.mjs` from `git show redblack:app/globals.css`:
  - every class selector gets an `rb-` prefix (CSS and ported TSX both rewritten);
  - `:root`, `html`, `body` and bare element selectors are rewritten to sit under `[data-rb]`;
  - CSS variables are renamed `--rb-*` so they cannot shadow three-pane tokens;
  - light/dark come from `[data-rb][data-mode="dark"]` / `prefers-color-scheme`, mirroring `redblack`'s own rules.
- Ported components import from `lib/redblack/*` and never from three-pane-only modules.

### 2. Switch in the layout
- A client component `UiSwitch` in `app/layout.tsx` reads `data-ui` (existing `useUiMode`, `kps-ui` key, pre-paint `THEME_INIT_SCRIPT` stay as-is).
- Default: renders current `HomeShell` + `{children}`. Brutal: renders `RbShell` (ported `HomeShell`) wrapping a ported home content tree in `<div data-rb>`.
- `RbShell` and `app/redblack.css` are loaded lazily (`next/dynamic`, CSS imported inside the lazy chunk) so default-UI visitors pay nothing.
- On non-home routes in Brutal (pass 1), the shell is `redblack`'s but the route content is unchanged three-pane content; this is an accepted interim state.
- Because the swap is a React re-render, Lenis, canvas/cursor listeners and intervals of the tree being replaced must clean up on unmount. Verified per component.

### 3. Way back
`redblack` has no rail 3, so the BRUTAL button disappears. `RbShell`'s nav gets an "EXIT BRUTAL" control calling the same `useUiMode().toggle`.

### 4. Not changing
Three-pane components, `app/globals.css`, `useUiMode`, `THEME_INIT_SCRIPT`, and the default-UI DOM/CSS. The only edits to existing files: `app/layout.tsx` (mount `UiSwitch`), and `docs/`.

## Known trade-offs
- The server always renders the default UI. A returning visitor whose saved mode is brutal sees the default UI briefly before the swap (the Boot overlay masks most of it). A cookie-based SSR fix would make every route dynamic, so it is rejected.
- Code duplication is deliberate: exact match with zero risk to the default UI.
- Prefixing by script is mechanical; selectors built dynamically in TSX (template-string class names) need manual review.

## Testing / verification
1. Check out `redblack` in a git worktree and run it on another port as the reference.
2. Screenshot reference vs Brutal ON at 1440px, 1100px, 390px, in light and dark; compare visually (layout, colours, hard shadows, nav, marquee, panels, cursor).
3. Screenshot default UI before and after the change at the same sizes; must be identical.
4. Toggle ON/OFF repeatedly: no console errors, no duplicated Lenis/cursor/listeners, `kps-ui` persists across reload, EXIT BRUTAL works.
5. `next build` + lint + typecheck pass; default-route JS does not include the redblack chunk.

## Out of scope (pass 2)
Blog, weekly, gallery, work/*, resume, places, specs styling in Brutal; SSR-correct first paint for returning Brutal users.
